# 林缘短旅：小闭环收尾

- 日期：2026-09-08。
- 用户要求：继续做成一个小闭环，保留原有进度。
- 范围：沿用 `chapter-one.html` 的连续森林与三种旧过溪解法，补齐玩家可读的起点、过程反馈、终点和安全重玩。没有生成新美术，没有增加新地图或提前发放魔法；没有提交或推送仓库。

## 可玩的完整段落

林缘旧路 → 受损溪路 → 选择松石垫脚／枯木搭桥／浅水绕行之一 → 可选观察陌生刻痕 → 抵达聚落边缘 → 显示结算与保存结果 → 可临时重玩。

这仍是约 1–3 分钟的开场短路线，不是计划中 10–15 分钟的完整开场，更不是约三小时的第一章。聚落内部、水车、媒介碎片、隐士教学及之后位点没有在本轮提前开放。

## 本轮实现

1. 开始时说明“沿旧路向东寻找落脚处”；到溪边后显示可用办法。第一块松石就位时显示 `1/2`，不提前宣布通路完成。
2. 互动成功和刻痕观察有短提示，目标随既有世界状态变化。没有另建一套任务完成标记。
3. `J` 或 HUD 的“笔记”打开旅途笔记，显示已采用的过溪方法和刻痕见闻；打开时暂停并清空运动输入，`J`、`Esc` 或关闭按钮返回游戏。
4. 抵达聚落边缘后释放运动输入，沿正常重力和摩擦落地、停稳后才显示“林间落脚”结算，避免冻结在腾空或跑步姿态。结算明确本段结束和后续尚未开放；没有瞬移落地或改变地形、存档结构。
5. 正常入口继续使用原 localStorage 主存档。结算只在实际写入成功后显示已保存；写入异常显示失败和重试按钮。生命周期保存也向 UI 报告失败，不将异常当成成功。
6. “临时重玩”生成独立 URL 和 sessionStorage 槽，不清除主存档；同 URL 刷新继续临时进度，关掉标签页可能失去临时进度。笔记和临时结算都提供“返回主进度”。这不是第二个永久存档槽，也不保证跨设备同步。
7. 绘制器与旅途 UI 合并进已有延迟加载场景模块，保持现有体积预算不变。场景模块未准备好时显示基础地形和人物、停止模拟推进；加载失败明确提示刷新且保留存档。

## 不变的逻辑边界

- 刻痕可以略过；观察只记录图形见闻，不授予含义、发音、学习证据、法术、MP 或额外物品。
- 原剧情／学习／MP／幂等回执／坏档校验仍由既有协调器与持久化层负责。
- 已提交的过溪方法在检查点回退后保留；重玩不冒充检查点回退。
- 旧的已结束存档继续保持原位置与姿态，不自动迁移或重跑剧情。要查看这轮新的落地结算过程，从终点选择临时重玩即可。
- 人物仍使用私有库 v0.6 开发候选，背景仍使用既有 v0.3 开发候选；公开生产构建保持程序化回退和素材审批门禁。
- 石木仍是旧的交互状态切换，溪水仍含预设材料口袋／静态水带。真实水流、连续石木运动、共享动态碰撞与保存仍属于未完成的 F3；本轮不能视为 F3–F5 验收通过。
