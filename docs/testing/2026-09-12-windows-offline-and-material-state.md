## 离线试玩交付

固定文件为 `exports/windows/tokipona-rpg-latest.exe`。它内含运行时、游戏与已有私人候选人物 v0.6／森林远景 v0.3，通过 `tokipona://game/chapter-one.html` 读取包内资源，不监听 HTTP 端口，不依赖校园网或开发服务。

渲染器启用沙箱和上下文隔离，关闭 Node 集成；无文件系统 IPC，拒绝外网请求、额外窗口、页面外导航和权限请求。不请求管理员权限，不关闭系统安全检查，不自动上传进度。桌面持久目录为 `%APPDATA%/tokipona-rpg`，与便携 EXE 解包目录分离。

浏览器与桌面进度各自保留，首次桌面启动是独立进度，本轮没有实现存档导入合并。测试使用单独的临时用户目录，不触碰用户的浏览器或桌面主档。

`pnpm run desktop:latest` 先验证公开生产构建及素材边界，再生成单独本地构建；分别启动未压缩程序与最终单文件 EXE，检验实际游戏加载、键盘移动、笔记、全屏和跨启动存档。新包全部通过后才原子替换固定文件，并清理旧包及本轮临时构建目录。失败时保留已有最新版。截图和报告保留在被忽略的 `.codex-tmp/desktop-latest/`，不是额外的游戏副本。

本地素材标记只在 `desktop/vite.config.ts` 中开启，默认公开构建仍关闭。现有私人素材由原哈希校验脚本同步，不从 Noita 或其他游戏提取素材，不将 EXE、截图或未审批素材加入公开 Git。构建工具版本固定为 Electron 44.3.0 与 electron-builder 26.15.3；官方运行时先核验 SHA-256 再解包。EXE 尚未发行签名和定制应用图标，仅为本机测试候选。

## F3 的实际开发增量

新增 `tokipona.material-grid.v0.1` 状态格式与 `MaterialGrid.save()`／`MaterialGrid.fromSave()`：

- 保留材料、温度、完整度、相变、燃烧、浮升、移动标记、模拟 tick、热更新相位和种子。
- 保存副本脱离运行中缓冲区；恢复前逐项检查 schema、尺寸、数组长度、稀疏数组、整数及范围，验证失败不会替换原模拟。
- 尺寸单边上限 4096、总格数上限 1,048,576，防止坏档造成过量分配。
- 修复 Uint32 移动标记计数回绕后的同 tick 重复移动风险。
- 六项新增测试覆盖 JSON 往返后逐 tick 一致、封闭水盆守恒、多次保存／恢复、挖开土壤通道后的水流与持续状态、缓冲隔离、坏档及计数回绕。

这只是 F3 的前置组件。森林障碍的旧材料编号与通用模拟不同，因此不能直接套用此格式或静默迁移旧档；本轮没有改写现有森林存档，也没有把旧溪水、松石和枯木伪装成已完成的共享动态物理。下一步才是局部溪路的材料转换、统一碰撞与连续石木运动，然后用原三条过溪路线验证。
