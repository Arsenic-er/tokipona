## 1. 这次决定了什么

用户要求：美术、地形、物理与操作表现直接以 Noita 为主要参照，先形成可玩的框架；道本语魔法、学习、世界观、任务及支线由本项目独立设计。

工程解释：保留独立游戏与当前工程，实现 Noita 式的横版材料世界，不改做 Noita 模组。官方说明其使用自研 C++ Falling Everything 引擎；本次查阅没有取得可以直接接入本项目的官方引擎包。因此不能把此路线描述成“现成引擎换皮即可完成”。也不因为这一方向就重写为 C++ 或整体更换引擎。

| 强参照 Noita 的部分 | 保持本项目设计的部分 |
| --- | --- |
| 小人物与巨大地貌、正侧面剖切构图、材料块面与细颗粒 | 森林地表开场、林间平地聚落、约三小时第一章 |
| 固体可破坏、粉末堆积、水流改道、局部热反应 | 先工具探索，获得媒介与碎片，再向隐士学习；不能开局直接施法 |
| 有重量的角色运动、稳定镜头、接地反馈 | 先走后跑、模拟摇杆、Windows 与 Android、慢探索节奏 |
| 环境规则可组合，结果不局限于一个交互按钮 | MP、媒介、语言掌握、环境共鸣共同限制法术；学习辅助游玩 |
| 从物理事实产生局部意外与新通路 | 持续存档、可延后主线、声望、生态及大型支线；不默认加入永久死亡或悬浮飞行 |

“光暗秩序崩塌”等异常物理以后通过同一套受限规则表达，不是用剧情随意关闭守恒或消耗检查。

## 2. 官方画面对照后的视觉约束

参考的是可读的画面结构，不只是暗色调与细粒子：

1. 地形是有厚度的岩土剖面；可走空间由实体之间的空隙形成。禁止大矩形平台涂一层噪点就当完成地貌。
2. 前景实体轮廓清楚，背景只有较低对比的山体、树干、遗迹剪影；背景不能看起来像可以站立的地面。
3. 大树、岩壁、水车等可以只露出局部。不是把完整概念画、完整树和完整建筑缩进一屏。
4. 森林地表应有天空开口、林冠与斜向树根。Noita 的地表截图也包含开阔天空；“参照 Noita”不等于把森林全改成黑山洞。
5. 岩土采用可辨识的材料块面，细节集中在断面、沉积层、湿边和破损处。避免每个像素独立随机明暗造成满屏闪点。
6. 近景材质颜色由世界坐标与稳定种子决定，不随帧数变色；水滴、碎屑才有运动。火光等强调局部作用点，主角不自带光圈。

画幅沿用纵向 360 逻辑像素、约 20 像素高人物，16:9 时横向约 640 像素；更宽窗口扩展横向视野。它们是本项目规格，不是声称测得的 Noita 原始参数。铺满可用窗口，不常驻侧栏、不拉伸人物。优先整倍像素采样；不能整倍覆盖时允许最近邻显示缩放，并实际检查不同 DPR 的闪烁和细线稳定性。

## 3. 第一段要做成什么样

只打磨现有开场里相邻的几个视野，不另建一个脱离主游戏的材料实验室：

| 顺序 | 玩家看见什么 | 玩家能做什么 | 必须可见的证据 |
| --- | --- | --- | --- |
| 林缘地表 | 上方林冠与天空、巨大树根、清晰薄草层和岩土断面 | 慢走、持续输入进入跑步、转身、跳下矮坡 | 腿部交换可读；脚踩实地；镜头低速跟随不抽动 |
| 浅溪与根系洞口 | 水进入低洼处，泥土、碎石、枯木具有不同轮廓 | 用普通工具疏通一段松土；推动石块或枯木；也可绕行 | 改变地形后水自行流入新空间；物体经过连续运动到达位置 |
| 林间草地出口 | 地势打开，远处有聚落活动痕迹 | 到达、回看自己的改动、观察未知刻痕 | 物理改变仍在；动物避开实体；观察不直接解锁魔法 |

开场仍按 10–15 分钟完整体验设计；当前灰盒路线只有约 1–3 分钟，不把它计成完整剧情时长。上述局部框架验收也不意味着三小时第一章已经完成。水车、碎片、隐士及之后位点仍按既定章节顺序出现，不前移来给测试场塞魔法。

## 4. 角色：保留造型，重做运行时可读性

之前生成的旅行者素材及其配色、服装、轮廓继续保留在私有素材库，作为造型依据。不能把“已生成”直接等同于“缩到约 20 像素后适合游戏”。

- 在最终逻辑像素尺度制作或整理运行时帧，统一画布、脚底锚点与体积。不能逐帧独立裁切缩放造成忽胖忽瘦。
- 头、躯干、近腿、远腿使用稳定色块；先读清姿态，再加入服装细节。去除无造型作用的游离亮点，不抹除必要的眼部或边缘像素。
- 走路与跑步都应包含左右触地、承重、交叉通过与抬腿姿态。帧数只是生产规格，不能代替动作质量。
- 步态相位跟随角色实际地面位移与步幅推进，限定可读节奏；不是走和跑都按全局时钟循环。走跑切换保留左右脚相位，碰墙停住后不得继续原地全速跑。
- 起步、刹停、转向和落地有短过渡。离地切换跳跃/下落姿态；脚步声绑定触地事件，不随任意动画帧重复触发。
- 维持轻推慢走、满推持续后加速跑的输入约定。现有速度、加速度与帧率均是候选参数，不能因参照 Noita 就擅自覆盖此前手感决定。
- 本轮先验证人类默认体型，保留未来自定义外观、多起源、多种族接口；不现在扩建角色创建系统。现有 `12×14` 碰撞体不随画布尺寸自动改动。

验收同时提供实际游戏大小的连续移动片段和放大帧条；慢走、走转跑、跑转停、左右转向、跳落都要看。正常速度下看不清脚部交换，就不能用“八帧已加载”判为通过。

| `src/runtime/forest-camera.ts` | 已有死区与阻尼，但逐 tick 整数化且有最小像素步长 | 保留浮点累积和渲染插值，只在最终显示阶段一致量化 |

本表说明代码接入状态，不是对整个项目“没有物理”的判断。基础材料测试通过也不证明森林已经达到 Noita 级模拟或性能。

### 第一轮模拟边界

1. 一套权威材料状态同时供渲染、角色碰撞、物体碰撞和生态落点查询。视觉碎片可以是装饰，但不能伪装成会挡路的实体。
2. 首段重点是岩石、松土、砂砾、水、木材及空气；火/热反应在这套状态稳定后加入同场景可控点。冰、复杂气体、电路和任意形状可碎刚体不作为首段前置。
3. 水与砂的活动单元为 1 逻辑像素，16 px 区块只负责组织。先做受控活动区域；不用整张 `10240×2880` 森林逐帧全量计算。
4. 封闭水槽测试必须保持水量；源、汇、跨区流量和相变要分别记账。可见溪流不能通过每帧重建原图偷偷补水或删水。基础算法不被宣称为完整流体力学。
5. 活动区边界要么落在真实封闭地形上，要么有明确流量交接；不得把看不见的材料墙放在可见溪流中。离屏休眠、载入恢复不丢流量或复制物质。
6. 首期石块和枯木采用少量简单形状刚体，支持重力、地面接触、推力，枯木另做水中浮力与阻水验证。不要求首期任意碎裂；禁止交互瞬移后再补一段烟尘假装滚动。
7. 角色碰撞需求解到接触面，不能在即将碰撞的子步整段提前停止而留缝。补落地容错、跳跃输入缓冲及短跳释放；具体数值留给手感校准。
8. 固定步长模拟与渲染频率分离；掉帧不能使物理时快时慢。记录实际设备、分辨率、活动格数、物体数、耗时及内存后再谈扩展，不先承诺手机整图模拟。

## 6. 原玩法怎样接进来

普通工具/已获授权法术 → 世界状态真实变化 → 根据通路、物体接触或水量判定结果 → 提交给现有任务与持久化系统 → NPC、生态、声望及学习反馈。

- 任务判定关注“是否形成可通行路径”等已定义结果，而不是只承认按过指定按钮。保留原有石路、枯木、浅水绕行的语义结果；组合方案只能归入明确允许的结果，不能任意生成奖励。
- 不用隐形门阻止已经物理可达的玩家，来强迫其先触发解法标记。剧情未满足时可不发奖励，但可达性与任务资格必须区分。
- 所有成功提交保持幂等；载入、回退检查点、再次经过不重复给学习证据或礼物。损坏存档保留原始字节，禁止静默覆盖。
- 旧材料口袋、森林块与通用模拟的材料 ID 并不相同；必须版本化转换，不能把旧数组直接按新枚举解释。新动态材料、物体位置、必要模拟状态一起持久化。
- 在本轮范围中，兔子只落到实体外且有支撑的栖地，鸟需要有净空的起飞路径。玩家改动地形后更新局部查询，不能继续沿旧路径穿墙；不扩建所有食物链物种。
- 未知刻痕仍只记录观察。获得媒介/碎片和隐士教学之前，不能为了展示特效开放 `telo`；以后相同水流机制才能被合法法术使用。

## 7. 新一轮顺序与可见验收

以下 F1–F5 是本次框架重构的阶段编号，不是追认以前“五步计划”已经完成。只在同一段可玩场景中推进；每次交付说明本轮具体审什么。

| 阶段 | 实施内容 | 给用户看的结果 / 通过条件 |
| --- | --- | --- |
| F1 画面结构 | 重做林缘—浅溪的实体轮廓、层次、地表与背景；接真实旅者候选 | 默认视野截图：森林可辨、通路可读、小人物与大环境成立；不依赖开发面板解释地面 |
| F2 角色与镜头 | 原生像素步态、位移同步、起停转向、接地及镜头插值 | 正常速度试玩：慢走也换腿，跑步有中间姿态，无白点闪动、悬空或低速跟随顿跳 |
| F3 材料与物体 | 接复用材料模拟、动态碰撞、松土破坏、真实水流与简单石/木刚体 | 挖开松土后水自行改道；枯木连续落下/入水；保存重进后结果一致 |
| F4 世界响应 | 迁移过溪结果、观察、生态避障、检查点与任务桥接 | 工具/绕行都能完成，动物不穿墙，奖励与学习证据不重复；不提前给魔法 |
| F5 联合验收 | 素材边界、回归、分辨率/帧率、完整路线与性能记录 | 一份可启动的整合候选、实际大小录像、明确缺陷表；代码通过与审美通过分开记录 |

F1 起即使用真实运行时代码核对可走面，F2 起即连测 F1；不能五个阶段分别做五个不互通的演示。F3 不达标时，不以“水流粒子更好看”替代物理验收。F5 不等于宣布第一章全部完成。

桌面目标保持 60 fps；Android 的同规则低预算模式必须在实际设备上另验，桌面浏览器触控模拟不计作安卓性能通过。首轮记录至少慢走、快跑、停转、跳落、水流繁忙、保存载入与窗口变化的结果。

## 8. 设计冲突处理与资源边界

- 第一章旧文档的 7+2 地点是剧情地点/子区，不再理解成每到一处都切屏；森林内部连续，森林与平原等大区仍分图。以 2026-08-30 地图规格为准。
- 开场保留地表森林，聚落保留平地草甸；局部根洞不改成地下出生整章。
- 2026-08-29 “先完整水车画面、再逐项接系统”的实施优先级由本文件 F1–F5 覆盖；水车概念图继续留作后续参考，不删除。
- 官方截图仅用于研究构图与表现，项目文档记录链接，不作为公开游戏纹理、图集或引擎代码导入。生产素材仍为自制或许可明确的资源。
- 原人物、环境、音频与候选资源继续放私有素材库；公开仓仅加入经过现有资产门禁的运行时导出。本轮设计不意味着旧候选已通过素材审批。
- 设计轮只新增设计与检查记录；用户随后要求继续，已进入第 10 节所列实施轮。原运行时、存档与素材保留，不以新框架为由删除旧玩法。

### 2026-09-13：步态认可，进入 F3 共享溪水增量
